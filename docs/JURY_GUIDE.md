## 1. Запуск системы

1. Установите и **запустите** Docker Desktop (или Docker Engine с Compose v2).
2. Положите датасет хакатона в `dataset/` (структура `dataset/{train,test,validate,labels}/`,
   `dataset/ndtp-telemetry-emulator.tar`).
3. Соберите и поднимите три модуля и источник потока:

   ```bash
   docker compose up -d --build
   docker compose ps
   ```

   Ожидаемый результат: `backend`, `ml-service`, `feeder` — `Up (healthy)`, `dashboard` — `Up`.
   Первая сборка занимает несколько минут, повторный холодный старт — около 8 с до первого прогноза.

4. Проверьте, что всё связано end-to-end:

   ```bash
   curl http://localhost:8000/api/status
   # {"mode":"online","link":"online","ml_available":true,...}
   ```

## 2. Подача потока данных

### 2.1. Исторический датасет (включён по умолчанию)

Сервис `feeder` воспроизводит реальную телеметрию `dataset/validate/traffic.csv` как NDTP-поток:
на каждый терминал своё TCP-соединение к `backend:9201`, handshake `NPH_SGC_CONN_REQUEST`, пауза 200 мс,
пакеты `NPH_SND_REALTIME` с ячейкой Nav00, reconnect при обрыве. Старт — 07:30 МСК (утренний пик), ускорение ×10.

Управление (или кнопки в шапке дашборда):

| Действие | Команда |
|---|---|
| Состояние реплея | `curl http://localhost:8090/status` |
| Ускорение ×30 | `curl -X POST http://localhost:8090/speed/30` |
| Пауза / продолжить | `curl -X POST http://localhost:8090/pause`, `curl -X POST http://localhost:8090/resume` |
| Перемотка на 17:00 МСК (14:00 UTC) | `curl -X POST "http://localhost:8090/seek?t=2026-01-06%2014:00:00"` |

Swagger фидера: http://localhost:8090/docs.

### 2.2. Штатный эмулятор NDTP

```bash
docker load -i dataset/ndtp-telemetry-emulator.tar
docker compose --profile emulator up -d
```

Контейнер `emulator-config` конфигурирует эмулятор из [scripts/emulator-config.json](../scripts/emulator-config.json)
на отправку в `backend:9201`. Эмулятор шлёт случайную навигацию с unitId, которых нет в расписании.
Его ТС появляются на карте серыми («без наряда»): это подтверждает, что парсер совместим с протоколом.
Проверка приёма:

```bash
curl http://localhost:8000/api/connections        # активные соединения терминалов
curl http://localhost:8000/api/metrics            # ndtp.parse_errors = 0
```

Остановка эмулятора: `docker compose --profile emulator stop emulator`.

### 2.3. Свой источник

Любой NDTP-клиент может слать кадры на `localhost:9201` (TCP). Проверить разбор одного кадра можно без сети:

```bash
curl -X POST http://localhost:8000/api/ndtp/parse -H "Content-Type: text/plain" \
  --data "7e7e26000000c15c0200cc110000000100650001000200000000001ba1b76a0d2b5f1609473821e0842d0030003d01060df0000e02"
```

## 3. Прогнозы и алерты

**Горизонт.** Для каждого ТС в момент T целевая остановка — первая остановка расписания с плановым временем
в окне **(T+10 мин, T+15 мин]**. Прогноз задержки на ней строится по потоку, раз в ≤ 1 с (событийно,
не позже 150 мс после нового пакета). Прогноз всегда относится к будущему событию.

**Что входит в алерт (карточку инцидента):**

- ТС и маршрут, уровень риска (жёлтый / красный), время открытия;
- прогноз опоздания на целевой остановке и текущее отклонение;
- P(опоздание > 2 мин);
- целевая остановка: план → прогноз;
- участок маршрута (от остановки → до остановки) с фактической и плановой скоростью;
- причина и рекомендация диспетчеру;
- ML-факторы — вклад паттернов в прогноз по SHAP.

**Где смотреть:**

| Где | Что |
|---|---|
| Дашборд, правая панель, вкладка «Инциденты» | Карточки инцидентов, отсортированы по серьёзности |
| Дашборд, клик по ТС | Карточка ТС: прогноз ML, P(late), скорость на сегменте, простой, ETA на 8 остановок, «Почему такой прогноз (SHAP)», график отклонения |
| `GET /api/incidents` | `open` — открытые, `resolved` — закрытые |
| `GET /api/vehicles` | Все ТС: уровень, прогноз, причина, `target_address`, `target_plan` |
| `GET /api/vehicles/{unit_id или tr_id}` | Полная карточка, включая `prediction.explanation` (SHAP) и признаки модели |
| `ws://localhost:8000/ws` | Поток снимков состояния раз в секунду |

Проверка горизонта через API: у каждого ТС `target_plan` отстоит от `last_seen` на 10–15 мин.

```bash
curl http://localhost:8000/api/vehicles
```

## 4. Дашборд диспетчера

**URL:** http://localhost:8080. Авторизации нет, логин и пароль не нужны.

| Зона | Что показывает |
|---|---|
| Шапка | Время потока (МСК), статус «Поток NDTP» и «ML-сервис», режим online/деградация, поиск ТС, скорость потока, кнопка «Обрыв потока», выбор подложки (2ГИС / Яндекс / OSM), тема |
| KPI | Число ТС по уровням риска (красный / жёлтый / зелёный / без прогноза), «Точность онлайн (MAE)» — модель против baseline по факту прибытия, «Задержка обработки» (пакет → прогноз, p95) |
| Карта | Маршрутная сеть по дорогам, ТС с цветом риска (дублируется формой маркера: круг / треугольник / ромб), участки сети с риском, расчётное положение при потере связи (пунктир) |
| Правая панель | Вкладки «Инциденты», «Все ТС», «What-if», «Маршруты», «Закрытые» |
| Низ | Интерактивный таймлайн (история до 6 ч и прогноз на 30 мин), риск по маршрутам, журнал событий, панель «Производительность» |

Типовой сценарий за 5 секунд: красные и жёлтые ТС видны на карте и в KPI → верхняя карточка во вкладке
«Инциденты» показывает, какое ТС, насколько и почему опоздает → «Отслеживать» ведёт карту за ТС,
«What-if» открывает моделирование мер, «Принять» отмечает инцидент в работе.

## 5. Проверка надёжности

| Сценарий | Как воспроизвести | Что увидеть |
|---|---|---|
| Обрыв связи с телематикой на 60 с | Кнопка «Обрыв потока» или `curl -X POST http://localhost:8090/outage/60` | Через 15 с баннер «Деградация», `GET /api/status` → `mode: degraded`, `link: lost`. Прогнозы продолжаются по последнему состоянию, ТС — пунктирное расчётное положение. После 60 с поток возвращается сам, режим `online` |
| Обрыв до ручного восстановления | `curl -X POST http://localhost:8090/outage/start` → `.../outage/stop` | То же, восстановление по команде |
| Падение ML-сервиса | `docker compose stop ml-service`, затем `docker compose start ml-service` | Режим `degraded`, причина «ML-сервис недоступен», карточки с тегом `baseline`. После старта прогнозы снова от модели |
| Мусор в канале | `curl -X POST http://localhost:8090/chaos/garbage` | `GET /api/metrics` → растёт `ndtp.skipped_garbage_bytes`, соединения не рвутся, `parse_errors` учитывают битые кадры |
| Нагрузка 1000 терминалов | `python scripts/load_test.py --units 1000 --rate 5 --duration 30` (нужен Python 3.12 на хосте) | ≈ 5000 пакетов/с без потерь (см. [scripts/out/load_test_1000x5.txt](../scripts/out/load_test_1000x5.txt)) |

## 6. Тесты

```bash
# Backend и NDTP-кодек (37 тестов)
docker run --rm -v "$PWD:/w" -w /w mos-transport/backend:1.0 \
  sh -c "pip install -q pytest && python -m pytest -q libs/ndtp/tests services/backend/tests"

# SHAP и метрики ML (6 тестов)
docker compose run --rm --no-deps -v "$PWD/services/ml_service/tests:/opt/ml/service/tests" ml-service \
  sh -c "pip install -q pytest && python -m pytest -q -p no:cacheprovider /opt/ml/service/tests"
```

PowerShell: замените `$PWD` на `${PWD}`, `\` в конце строки — на `` ` `` или запишите команду в одну строку.
В Git Bash на Windows перед командами с путями внутри контейнера выполните `export MSYS_NO_PATHCONV=1`.

## 8. What-if и дообучение

- **What-if:** вкладка «What-if» на дашборде или кнопка «What-if» в карточке инцидента. Выберите сценарий
  (резерв, объезд, светофорный приоритет, эффект домино, пропуск остановок, поломка, ДТП, засор, пробки),
  при желании «+ Добавить в комбинацию» → «Рассчитать» → сравнение «до/после» на карте и в таблице, рекомендация.
  «Применить к живому прогнозу» включает сценарий в текущий прогноз, «Снять все» — отменяет.
  Поломка, ДТП и засор также инжектируются в поток. API: `POST /api/whatif/simulate`, `POST /api/whatif/apply`.
- **Дообучение модели** (только из консоли):

  ```bash
  docker compose run --rm --no-deps ml-service python -m app.finetune             # сравнить с текущей
  docker compose run --rm --no-deps ml-service python -m app.finetune --activate  # заменить, если лучше
  docker compose restart ml-service
  ```

  Подробности — [ML.md → Дообучение](ML.md#9-дообучение).

## 9. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `error during connect ... dockerDesktopLinuxEngine: The system cannot find the file specified` | Docker Desktop не запущен. Запустите его и дождитесь статуса «Engine running» |
| `COPY dataset/... not found` при сборке | Нет папки `dataset/` с датасетом (см. [§1](#1-запуск-системы)) |
| Порт занят (`8000`, `8001`, `8080`, `8090`, `9201`) | Освободите порт или поменяйте левую часть `ports:` в `docker-compose.yml` |
| Карта серая без подложки | Нет интернета для тайлов. Прогнозы и дашборд работают; переключите подложку на OSM или дождитесь сети |
| ML на дашборде «недоступен» сразу после старта | ML-сервис грузит модель несколько секунд; backend в это время работает на baseline и переключается сам |
